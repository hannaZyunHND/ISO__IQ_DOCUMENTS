# SOP-04.1: LỰA CHỌN VÀ TRIỂN KHAI HỆ THỐNG

## 1. MỤC ĐÍCH
Quy định quy trình lựa chọn và triển khai hệ thống LMS/CRM/HRM, đảm bảo:
- Chọn đúng giải pháp phù hợp
- Triển khai thành công và đúng tiến độ
- Trong ngân sách
- Đáp ứng yêu cầu nghiệp vụ
- Nền tảng vững chắc cho vận hành

## 2. QUY TRÌNH LỰA CHỌN

### 2.1. Bước 1: Requirements gathering (4-6 tuần)

#### 2.1.1. Stakeholder workshops
```
Workshops by system:

LMS Workshop (Academic team):
- Current challenges
- Must-have features
- Nice-to-have features
- Integration needs
- User experience expectations

CRM Workshop (Marketing, Admissions):
- Lead management needs
- Communication requirements
- Reporting needs
- Automation desires

HRM Workshop (HR team):
- Core HR functions
- Employee self-service
- Reporting needs
- Compliance requirements
```

#### 2.1.2. Requirements document
```
SYSTEM REQUIREMENTS DOCUMENT

1. BUSINESS REQUIREMENTS:
   - Business objectives
   - Success criteria
   - KPIs

2. FUNCTIONAL REQUIREMENTS:
   Must-have (P0):
   - [Requirement 1]
   - [Requirement 2]
   
   Should-have (P1):
   - [Requirement 3]
   
   Nice-to-have (P2):
   - [Requirement 4]

3. NON-FUNCTIONAL REQUIREMENTS:
   - Performance (response time, concurrent users)
   - Scalability (growth capacity)
   - Security (compliance, encryption)
   - Availability (uptime, support hours)
   - Usability (ease of use, mobile)

4. INTEGRATION REQUIREMENTS:
   - Systems to integrate
   - Data to sync
   - Real-time vs. batch

5. TECHNICAL REQUIREMENTS:
   - Infrastructure (cloud/on-premise)
   - Browsers supported
   - Mobile apps
   - APIs available

6. SUPPORT REQUIREMENTS:
   - Training needs
   - Documentation
   - Ongoing support
   - Upgrade path

7. BUDGET & TIMELINE:
   - Budget range
   - Go-live target
   - Constraints
```

### 2.2. Bước 2: Market research (2-3 tuần)

#### 2.2.1. Identify vendors
```
Sources:
- Analyst reports (Gartner, Forrester)
- Industry reviews (G2, Capterra)
- Peer recommendations
- Conferences
- Web research

Create longlist: 10-15 vendors
```

#### 2.2.2. Initial screening
```
Criteria:
□ Meets must-have requirements
□ Established vendor (≥3 years)
□ Education sector experience
□ Good reviews (≥4.0/5.0)
□ Pricing within budget
□ Local support (Vietnam)
□ Scalability

Result: Shortlist 3-5 vendors
```

### 2.3. Bước 3: Vendor evaluation (4-6 tuần)

#### 2.3.1. RFP process
```
Timeline:
Week 1: Issue RFP
Week 2-3: Vendor prepares responses
Week 4: Submit proposals
Week 5: Evaluate responses
Week 6: Demos và presentations
```

#### 2.3.2. Evaluation criteria
```
Criteria | Weight | Vendor A | Vendor B | Vendor C
---------|--------|----------|----------|----------
Functionality | 30% | [Score] | [Score] | [Score]
Usability | 20% | [Score] | [Score] | [Score]
Integration | 15% | [Score] | [Score] | [Score]
Vendor strength | 15% | [Score] | [Score] | [Score]
Pricing | 10% | [Score] | [Score] | [Score]
Implementation | 10% | [Score] | [Score] | [Score]
---
Total | 100% | [Total] | [Total] | [Total]
```

#### 2.3.3. Product demos
```
Demo agenda (2-3 giờ):
1. Vendor presentation (30 phút)
2. Feature walkthrough (60 phút):
   - Core features
   - Must-have requirements
   - Integration demo
3. Q&A (30 phút)
4. Technical deep-dive (30 phút)

Attendees:
- Business owners
- Key users
- IT team
- Procurement
```

#### 2.3.4. Reference checks
```
Contact 2-3 references per vendor:
- Similar school size
- Same region (nếu có thể)
- Been using ≥1 năm

Questions:
- Implementation experience?
- Pros và cons?
- Support quality?
- Hidden costs?
- Would you choose again?
- Any regrets?
```

### 2.4. Bước 4: Selection decision (1-2 tuần)

#### 2.4.1. Scoring và comparison
```
Create comparison matrix:
- Feature-by-feature
- Pricing breakdown
- Total cost of ownership (TCO)
- Risk assessment
- Recommendation
```

#### 2.4.2. Business case
```
BUSINESS CASE DOCUMENT

1. Executive summary
2. Current state problems
3. Proposed solution
4. Alternatives considered
5. Cost-benefit analysis:
   - Implementation costs
   - Annual costs
   - Benefits (quantified)
   - ROI calculation
   - Payback period
6. Risks và mitigation
7. Recommendation
8. Approval request
```

#### 2.4.3. Approval
```
Present to:
- IT Steering Committee
- BGH
- CFO (budget approval)
- Board (major investments)

Decision: Approve / Request more info / Decline
```

### 2.5. Bước 5: Contract negotiation (2-4 tuần)

#### 2.5.1. Key terms
```
Negotiable items:
- Pricing (discounts, payment terms)
- Scope (features included)
- Implementation timeline
- Support levels (SLA)
- Training included
- Customization allowance
- Data ownership
- Exit provisions
- Renewal terms
```

#### 2.5.2. Contract review
```
Legal review:
- Liability caps
- Indemnification
- Data protection
- IP ownership
- Termination clauses
- Dispute resolution
- Governing law

IT review:
- Technical specifications
- SLAs
- Integration commitments
- Security requirements
```

## 3. IMPLEMENTATION PROCESS

### 3.1. Project planning (2 tuần)

#### 3.1.1. Project charter
```
PROJECT CHARTER - [System] Implementation

Objectives:
- [Objective 1]
- [Objective 2]

Scope:
- In scope: [...]
- Out of scope: [...]

Timeline:
- Kickoff: [Date]
- Go-live: [Date]
- Duration: [X months]

Budget: [Amount]

Team:
- Sponsor: [Name]
- Project Manager: [Name]
- Business Lead: [Name]
- Technical Lead: [Name]
- Vendor PM: [Name]

Success criteria:
- [Criteria 1]
- [Criteria 2]
```

#### 3.1.2. Project plan
```
Phases:
1. Initiation (2 tuần)
2. Design (4 tuần)
3. Build (6 tuần)
4. Test (4 tuần)
5. Training (3 tuần)
6. Deployment (2 tuần)
7. Hypercare (4 tuần)

Total: ~6 tháng (typical)
```

### 3.2. Implementation phases

#### 3.2.1. Design phase
```
Activities:
- Detailed requirements
- System configuration design
- Integration design
- Data migration plan
- Training plan
- Cutover plan

Deliverables:
- Design document
- Configuration workbook
- Integration specification
- Migration plan
- Training curriculum
```

#### 3.2.2. Build phase
```
Activities:
- System configuration
- Customization development
- Integration development
- Data cleansing
- Test environment setup

Deliverables:
- Configured system
- Custom code
- Integration connectors
- Clean data
- Test scripts
```

#### 3.2.3. Test phase
```
Test types:
1. Unit testing (developers)
2. Integration testing (IT)
3. User acceptance testing (business users)
4. Performance testing (IT)
5. Security testing (security team)

Pass criteria: ≥ 95% of test cases passed
```

#### 3.2.4. Deployment
```
Approach options:
1. Big bang:
   - Switch all at once
   - High risk, fast
   
2. Phased:
   - Roll out by department/grade
   - Lower risk, slower
   
3. Parallel:
   - Run old và new together
   - Lowest risk, highest cost

Recommendation: Phased (for schools)
```

### 3.3. Go-live support

#### 3.3.1. Hypercare period (4 tuần)
```
Support model:
- Extended hours (7am-7pm)
- Dedicated team
- Fast response times
- Daily standups
- Issue triage
- Quick fixes

Activities:
- Monitor system closely
- Resolve issues rapidly
- Gather feedback
- Make adjustments
- Document lessons
```
