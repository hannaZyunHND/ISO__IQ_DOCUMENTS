# SOP-05.2: PILOT VÀ THỬ NGHIỆM

## 1. MỤC ĐÍCH
Quy định quy trình pilot và thử nghiệm công nghệ mới, đảm bảo:
- Test trong môi trường thực
- Đo lường hiệu quả chính xác
- Rủi ro được kiểm soát
- Học hỏi trước khi scale
- Quyết định dựa trên data

## 2. PILOT DESIGN

### 2.1. Pilot planning

#### 2.1.1. Define pilot scope
```
Xác định:
1. Objectives:
   - What testing? (hypothesis)
   - What measuring? (metrics)
   - Success criteria?

2. Scope:
   - Which subjects/classes?
   - Which grade levels?
   - How many students?
   - How many teachers?
   - Duration?

3. Resources:
   - Budget
   - Equipment
   - Personnel
   - Time

Example:
Pilot: AI adaptive learning platform
Subjects: Math
Grades: 6-8
Students: 90 (3 classes)
Teachers: 3
Duration: 1 semester (4 tháng)
Budget: 50 triệu VNĐ
```

#### 2.1.2. Selection criteria
```
Pilot participants:
Teachers:
- Volunteer (willing)
- Tech-savvy (comfortable)
- Influential (can advocate)
- Diverse (different styles)

Students:
- Representative sample
- Mix of abilities
- Parental consent
- Willing participants
```

### 2.2. Pilot preparation

#### 2.2.1. Setup (2-4 tuần)
```
Technical:
□ Procure equipment/software
□ Install và configure
□ Test functionality
□ Setup accounts
□ Integration (nếu cần)
□ Backup plan ready

Training:
□ Train teachers (4-8 giờ)
□ Student orientation (1-2 giờ)
□ Parent information session
□ Support materials prepared

Communication:
□ Inform stakeholders
□ Consent forms (parents)
□ FAQ published
□ Support channels ready
```

## 3. PILOT EXECUTION

### 3.1. Implementation approach

#### 3.1.1. Phased rollout
```
Week 1-2: Introduction
- Setup và familiarization
- Basic usage
- Support intensive

Week 3-6: Active use
- Regular integration into lessons
- Experiment với features
- Gather initial feedback

Week 7-14: Optimization
- Refine usage
- Advanced features
- Collect comprehensive data

Week 15-16: Wrap-up
- Final assessments
- Surveys
- Synthesis
```

#### 3.1.2. Support structure
```
During pilot:
- Dedicated support person
- Daily check-ins (first 2 tuần)
- Weekly meetings (with teachers)
- Quick issue resolution
- Continuous feedback collection
```

### 3.2. Data collection

#### 3.2.1. Quantitative data
```
Learning outcomes:
- Pre-test scores
- Post-test scores
- Progress tracking
- Completion rates
- Time on task

Engagement:
- Login frequency
- Session duration
- Activities completed
- Interaction rates

Usage:
- Feature utilization
- Peak times
- Technical issues
- Error rates
```

#### 3.2.2. Qualitative data
```
Methods:
- Surveys (students, teachers, parents)
- Interviews (in-depth)
- Focus groups
- Observations (classroom)
- Teacher journals

Questions:
- Experience?
- What worked?
- What didn't?
- Suggestions?
- Continue using?
```

### 3.3. Monitoring và adjustment

#### 3.3.1. Weekly reviews
```
Review meeting (1 giờ):
- Progress update
- Issues encountered
- Feedback highlights
- Adjustments needed
- Action items

Participants:
- Pilot teachers
- Innovation team
- IT support
```

#### 3.3.2. Mid-pilot checkpoint (Week 8)
```
Assessment:
- On track với objectives?
- Data collection working?
- Issues manageable?
- Adjustments needed?

Decision:
- Continue as planned
- Make adjustments
- Extend pilot
- Stop early (nếu clearly not working)
```

## 4. EVALUATION

### 4.1. Data analysis

#### 4.1.1. Learning impact analysis
```
Compare:
- Pilot class vs. control class
- Pre-test vs. post-test
- Expected vs. actual improvement

Statistical tests:
- T-test (mean differences)
- Effect size (Cohen's d)
- Significance (p-value)

Interpretation:
- Statistically significant? (p<0.05)
- Practically significant? (effect size ≥0.5)
- Cost-effective? (improvement worth investment)
```

#### 4.1.2. Engagement analysis
```
Metrics:
- Engagement score (1-5)
- Time spent
- Completion rates
- Voluntary usage

Comparison:
- Pilot vs. traditional methods
- Across student segments
- Teacher feedback correlation
```

#### 4.1.3. Usability analysis
```
System Usability Scale (SUS):
- 10-question survey
- Score 0-100
- Benchmark: ≥68 (average), ≥80 (good)

Issues:
- Technical problems frequency
- Support requests
- Workarounds needed
```

### 4.2. Pilot report

#### 4.2.1. Report structure
```
PILOT EVALUATION REPORT (20-30 trang)

EXECUTIVE SUMMARY (2 trang)
- Pilot overview
- Key findings
- Recommendation

1. INTRODUCTION (3 trang)
   - Background
   - Objectives
   - Methodology

2. IMPLEMENTATION (3 trang)
   - Setup
   - Timeline
   - Participants
   - Activities

3. RESULTS (8 trang)
   - Learning outcomes
   - Engagement
   - Usability
   - Technical performance

4. FEEDBACK (4 trang)
   - Teacher feedback
   - Student feedback
   - Parent feedback

5. COST ANALYSIS (3 trang)
   - Actual costs
   - Projected costs (scale)
   - ROI estimate

6. LESSONS LEARNED (2 trang)
   - What worked
   - What didn't
   - Adjustments needed

7. RECOMMENDATION (2 trang)
   - Scale / Pivot / Stop
   - Implementation plan (nếu scale)
   - Budget request

8. APPENDICES
```

### 4.3. Decision making

#### 4.3.1. Go/No-go criteria
```
SCALE (Triển khai rộng) if:
✅ Learning outcomes improved (≥10%)
✅ Engagement high (≥4.0/5.0)
✅ Teacher satisfaction (≥80% want to continue)
✅ Student satisfaction (≥4.0/5.0)
✅ Technical stability (≥95% uptime)
✅ ROI positive (or strategic value clear)

PIVOT (Điều chỉnh) if:
⚠️ Mixed results
⚠️ Some value but needs changes
⚠️ Fixable issues identified

STOP (Dừng lại) if:
❌ No learning improvement
❌ Low engagement
❌ Technical problems severe
❌ Costs too high
❌ Better alternatives exist
```

#### 4.3.2. Approval process
```
Present to:
1. Innovation Committee
2. Academic Committee
3. BGH
4. Board (nếu major investment)

Decision: [Scale / Pivot / Stop]
```

## 5. PILOT TYPES

### 5.1. Proof of Concept (POC)

#### 5.1.1. Characteristics
```
Purpose: Validate technical feasibility
Duration: 2-4 tuần
Participants: Small (5-10 users)
Scope: Narrow (specific feature)
Environment: Lab/controlled
Success: Technical viability proven
```

### 5.2. Proof of Value (POV)

#### 5.2.1. Characteristics
```
Purpose: Validate business/educational value
Duration: 1-2 tháng
Participants: Medium (30-50 users)
Scope: Moderate (core features)
Environment: Semi-production
Success: Value demonstrated, ROI projected
```

### 5.3. Pilot (Full)

#### 5.3.1. Characteristics
```
Purpose: Test at scale, operational readiness
Duration: 3-6 tháng (semester)
Participants: Large (100-200 users)
Scope: Comprehensive
Environment: Production
Success: Ready to scale, all criteria met
```

## 6. RISK MANAGEMENT

### 6.1. Pilot risks

#### 6.1.1. Common risks
```
Risk | Mitigation
-----|------------
Low participation | Select volunteers, incentivize
Technical failures | Backup plan, quick support
Teacher overload | Adequate training, reduce other work
Student resistance | Gamification, peer champions
Data issues | Privacy review, consent
Cost overruns | Buffer budget, monitor closely
```

#### 6.1.2. Contingency plans
```
If major issues:
- Pause pilot
- Fix issues
- Resume or terminate
- Refund/return (nếu purchased)
```

### 6.2. Ethical considerations

#### 6.2.1. Informed consent
```
Required from:
- Parents (for students <18)
- Teachers (participants)
- Students (assent, nếu older)

Inform about:
- Purpose
- What involved
- Risks và benefits
- Voluntary (can withdraw)
- Data usage
- Privacy protection
```

#### 6.2.2. Control group ethics
```
If using control group:
- Fair selection (random)
- No disadvantage to control
- Offer to control after pilot (nếu successful)
- Monitor both groups
```
